Goal of this computing lab session

The goal of this lab is to build an annual space–time model for Italy, fit each of the space–time interaction types in turn, and then deal with the practical side of running models at scale.

What’s going to happen in this lab session?

During this lab session, we will:

  1. Build an annual space–time model one f() term at a time;
  2. Fit all four interaction types and compare them;
  3. Fit the restricted linear-slope alternative;
  4. Make the fits cheaper using INLA’s approximation settings; and
  5. Turn the model into a script a cluster could run.

Introduction

In the INLA lab we fitted pooling models to September 2018 only. Everything ran in seconds, so we could concentrate on the modelling.

Here we keep several years, and add the space–time interaction from the spatiotemporal session. The methods do not change; what changes is what each choice costs.

Nothing here needs a cluster account. Everything runs on your laptop, but the scripts are written so that they would work on a cluster with minimal edits.

Keep those numbers in mind. Every one of the four interaction types will have exactly \(N_p \times N_t\) latent values.

The model

Likelihood \[ \begin{split} y_{jt} &\sim \text{Pois}(E_{jt} \mu_{jt}) \\ \log(\mu_{jt}) &= \alpha + b_j + \gamma_t + \nu_{jt} \end{split} \]

where \(b_j\) is the BYM2 spatial baseline, \(\gamma_t\) is a smooth RW2 trend across years, and \(\nu_{jt}\) is the space–time interaction. We will specify \(\nu_{jt}\) five different ways.

Because the expected counts go in through E =, the linear predictor is the log relative risk directly. exp() of it is the SMR, with no offset to subtract.

The priors are shared across every fit below.

hyper_pc  <- list(prec = list(prior = "pc.prec", param = c(1, 0.01)))
hyper_int <- list(prec = list(prior = "pc.prec", param = c(0.5, 0.01)))

hyper_bym2 <- list(
  prec = list(prior = "pc.prec", param = c(1, 0.01)),
  phi  = list(prior = "pc",      param = c(0.5, 0.5))
)

To keep the fits comparable, let’s wrap the inla() call so that only the formula changes.

fit_model <- function(formula, ...) {
  inla(
    formula,
    family = "poisson",
    E      = expected,
    data   = data,
    control.fixed     = list(mean.intercept = 0, prec.intercept = 0.04),
    control.predictor = list(compute = TRUE),
    control.compute   = list(dic = TRUE, waic = TRUE, config = TRUE),
    ...
  )
}

The maps now change from year to year. But every province rises and falls in exactly the same way, shifted by its own baseline. This is the separable model, and the rest of the lab relaxes it.

Type I interaction

Priors \[ \nu_{jt} \sim N(0, \sigma^2_\nu) \quad j = 1,..., N_p, \ t = 1,..., N_t \]

Type II interaction

\[ \boldsymbol{\nu}_{j\cdot} \sim \text{RW1} \quad \text{independently for each } j \]

Each province gets its own smooth trend, unrelated across the map. This is the group = construction: IID over provinces, RW1 across the grouped years.

    hyper = hyper_pc) +

Type III interaction

\[ \boldsymbol{\nu}_{\cdot t} \sim \text{ICAR}(W) \quad \text{independently for each } t \]

Type IV interaction

\[ \boldsymbol{\nu} \sim \text{ICAR}(W) \otimes \text{RW1} \]

Smooth in both dimensions at once: a province’s departure resembles its neighbours’ and its own value last year.

Strictly, type IV needs extra sum-to-zero constraints to be fully identifiable alongside the main effects: one per province and one per year, supplied through extraconstr. Without them the interaction is partly confounded with the spatial and temporal main effects, so the split between them is not unique. Plenty of published type IV models are fitted exactly as above. It matters if you want to interpret the main effects separately; it matters much less for the fitted values, or for the comparison we are making here.

To map the interaction we need to line the random effects up with the data. For a grouped term the effects run province-fastest within each year, which is not the order our data is sorted in, so let’s join on the indices rather than trusting position.

add_nu <- function(m, term, grouped = TRUE) {
  re <- m$summary.random[[term]]
  if (grouped) {
    key <- expand_grid(id_year_int = 1:Nt, id_space_int = 1:Np) |>
      mutate(nu = re$mean[1:(Np * Nt)])
    data |> left_join(key, by = c("id_space_int", "id_year_int"))
  } else {
    data |> mutate(nu = re$mean[id_cell])
  }
}

int_maps <- function(m, term, label, grouped = TRUE) {
  add_nu(m, term, grouped) |>
    left_join(shp_italy, by = "SIGLA") |>
    st_as_sf() |>

    geom_sf(colour = NA) +

                                    name = expression(nu[jt])) +

}

Linear slopes

All four types cost \(N_p \times N_t\) latent values. The alternative gives each province a single linear departure from the common trend, with the slopes smoothed spatially.

\[ \nu_{jt} = \nu_j \cdot c_t, \qquad \boldsymbol{\nu} \sim \text{ICAR}(W) \]

The second argument to f() is a weight, so each province gets one coefficient on centred year.

formula_slopes <- deaths ~ 1 +
  f(id_space, model = "bym2", graph = g, scale.model = TRUE,
    hyper = hyper_bym2) +

    hyper = hyper_pc) +
  f(id_space_int, id_year_c, model = "besag", graph = g,

The rough/full workflow

The expensive part of a large fit is the optimisation over the hyperparameters. The location of the mode barely depends on how accurate the latent-field approximation is, so we can find it cheaply first.

Stage 1 uses the Gaussian approximation and empirical Bayes, and computes nothing.

t_rough <- system.time(
  fit_rough <- inla(
    model_formula,
    family = "poisson",
    E      = expected,
    data   = data,
    control.fixed     = list(mean.intercept = 0, prec.intercept = 0.04),
    control.predictor = list(compute = FALSE),
    control.inla      = list(strategy = "gaussian", int.strategy = "eb"),
    control.compute   = list(dic = FALSE, config = FALSE)
  )
)

Stage 2 warm-starts from that mode via control.mode, and only now pays for accuracy.

t_full <- system.time(
  fit <- inla(
    model_formula,
    family = "poisson",
    E      = expected,
    data   = data,
    control.fixed     = list(mean.intercept = 0, prec.intercept = 0.04),
    control.predictor = list(compute = TRUE),
    control.mode      = list(theta = fit_rough$mode$theta, restart = TRUE),
    control.inla      = list(strategy = "simplified.laplace", int.strategy = "auto"),
    control.compute   = list(dic = TRUE, config = TRUE)
  )
)

On a model this small the staging may not win, because the fixed overhead of a second inla() call is a large share of the total. The gap opens up as models grow, which is why the national model uses it.

This is worth seeing rather than being told. Raise n_years, re-run, and watch the two-stage total pull ahead of the one-stage fit.

For a national-scale model the fitted object runs to tens of gigabytes. The summary table, the posterior draws of anything we report, and a record of the formula and priors are what to keep.

From interactive session to script

On a cluster there is no “Run current chunk”. The model has to be a standalone script that loads what it needs, fits, saves and exits.

# fit_spacetime.R
library(here); library(tidyverse); library(INLA); library(sf); library(spdep)

n_years <- 5

data <- read_rds(here("data", "italy", "italy_mortality.rds")) |>
  group_by(SIGLA, year) |>
  summarise(deaths = sum(deaths), expected = sum(expected), .groups = "drop") |>
  arrange(SIGLA, year) |>
  filter(year %in% tail(sort(unique(year)), n_years)) |>
  mutate(id_space     = as.integer(factor(SIGLA)),
         id_year      = as.integer(factor(year)),
         id_space_int = id_space,
         id_year_int  = id_year,
         id_cell      = row_number(),
         id_year_c    = id_year - mean(unique(id_year)))

g <- inla.read.graph(here("data", "italy", "italy.adj"))

hyper_pc   <- list(prec = list(prior = "pc.prec", param = c(1, 0.01)))
hyper_int  <- list(prec = list(prior = "pc.prec", param = c(0.5, 0.01)))
hyper_bym2 <- list(prec = list(prior = "pc.prec", param = c(1, 0.01)),
                   phi  = list(prior = "pc",      param = c(0.5, 0.5)))

model_formula <- deaths ~ 1 +
  f(id_space, model = "bym2", graph = g, scale.model = TRUE,
    hyper = hyper_bym2) +
  f(id_year,  model = "rw2", constr = TRUE, scale.model = TRUE,
    hyper = hyper_pc) +
  f(id_space_int, id_year_c, model = "besag", graph = g,
    scale.model = TRUE, hyper = hyper_int)

fit_rough <- inla(
  model_formula, family = "poisson", E = expected, data = data,
  control.fixed     = list(mean.intercept = 0, prec.intercept = 0.04),
  control.predictor = list(compute = FALSE),
  control.inla      = list(strategy = "gaussian", int.strategy = "eb"),
  control.compute   = list(dic = FALSE, config = FALSE)
)

message("Rough done. Mode: ",
        paste(round(fit_rough$mode$theta, 3), collapse = ", "))

fit <- inla(
  model_formula, family = "poisson", E = expected, data = data,
  control.fixed     = list(mean.intercept = 0, prec.intercept = 0.04),
  control.predictor = list(compute = TRUE),
  control.mode      = list(theta = fit_rough$mode$theta, restart = TRUE),
  control.inla      = list(strategy = "simplified.laplace", int.strategy = "auto"),
  control.compute   = list(dic = TRUE, config = TRUE)
)

message("Full done.")

# saveRDS(fit, here("output", paste0("fit_spacetime_", Sys.Date(), ".rds")))

This is exactly the code we ran above, in order, with message() markers between the stages. Those markers end up in the job’s log file, so when a job dies we know which stage died.

Note there is no setwd() and no absolute paths. Using here() means the script runs identically on a laptop and on a cluster.

The sbatch script

The scheduler needs a short shell script describing what to run and what resources it needs.

#!/bin/bash
#SBATCH --job-name=italy-spacetime
#SBATCH --partition=short
#SBATCH --time=02:00:00
#SBATCH --cpus-per-task=1
#SBATCH --mem=16G
#SBATCH --output=output/%x-%j.out
#SBATCH --error=output/%x-%j.err

set -euo pipefail

module purge

export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1

cd ~/repos/italy-spacetime

apptainer exec --cleanenv \
  --bind "$PWD":"$PWD" \
  --pwd "$PWD" \
  ~/r_spatial.sif \
  Rscript fit_spacetime.R

Submission is then one line: sbatch run_fit_spacetime.sbatch.

--time and --mem are a contract with the scheduler. Exceed either and the job is killed; request far too much and we wait much longer in the queue. A sensible approach is to run once at modest scale, check what was used with seff <jobid>, then request somewhat above that.

The apptainer exec line runs the script inside a container: a single .sif file holding a frozen operating system, R, INLA and every dependency. That file is the computational environment, and archiving it with the paper means the analysis reruns identically in five years.

For national-scale models the requests are much larger. Real jobs ask for things like --mem=700G on a high-memory node, with a 12-hour wall time. The structure of the script is identical; only the numbers change.

Job arrays

We fitted the five interaction specifications one after another above. They share no state, so they can all run at once as a job array.

Let’s parameterise the script by a task ID.

# fit_interaction.R
task  <- as.integer(commandArgs(trailingOnly = TRUE)[1])
label <- c("typeI", "typeII", "typeIII", "typeIV", "slopes")[task]
message("Task ", task, ": interaction = ", label)

# ... data, graph and priors exactly as in fit_spacetime.R ...

base <- deaths ~ 1 +
  f(id_space, model = "bym2", graph = g, scale.model = TRUE, hyper = hyper_bym2) +
  f(id_year,  model = "rw2", constr = TRUE, scale.model = TRUE, hyper = hyper_pc)

model_formula <- switch(
  label,
  typeI   = update(base, ~ . + f(id_cell, model = "iid", hyper = hyper_int)),
  typeII  = update(base, ~ . + f(id_space_int, model = "iid", hyper = hyper_int,
                                 group = id_year_int,
                                 control.group = list(model = "rw1",
                                                      scale.model = TRUE))),
  typeIII = update(base, ~ . + f(id_space_int, model = "besag", graph = g,
                                 scale.model = TRUE, hyper = hyper_int,
                                 group = id_year_int,
                                 control.group = list(model = "iid"))),
  typeIV  = update(base, ~ . + f(id_space_int, model = "besag", graph = g,
                                 scale.model = TRUE, hyper = hyper_int,
                                 group = id_year_int,
                                 control.group = list(model = "rw1",
                                                      scale.model = TRUE))),
  slopes  = update(base, ~ . + f(id_space_int, id_year_c, model = "besag",
                                 graph = g, scale.model = TRUE,
                                 hyper = hyper_int))
)

# ... rough then full fit, exactly as in fit_spacetime.R ...

message("Task ", task, ": done. DIC = ", round(fit$dic$dic, 1))

# saveRDS(fit, here("output", paste0("fit_", label, "_", Sys.Date(), ".rds")))

The sbatch script then needs an --array line and the task ID passed through.

#SBATCH --array=1-5
#SBATCH --output=output/%x-%A_%a.out
#SBATCH --error=output/%x-%A_%a.err

apptainer exec --cleanenv --bind "$PWD":"$PWD" --pwd "$PWD" \
  ~/r_spatial.sif \
  Rscript fit_interaction.R ${SLURM_ARRAY_TASK_ID}

One submission, five jobs running at the same time, five outputs. The log names use %A_%a so each task writes its own files.

We can rehearse the pattern locally, no cluster required.

for i in 1 2 3 4 5; do Rscript fit_interaction.R $i; done

The same pattern covers models per sex, per cause of death, or per pollutant. In general, parallelise across models before parallelising within one.

Closing remarks

In this lab session, we have built an annual space–time model for Italy one term at a time, and fitted every space–time interaction type in INLA. We then made the same model cheaper to fit, and packaged it as a script a cluster could run.

At 107 provinces and a handful of years the choice between interaction types is a scientific one, because every one of them fits. The reason to know what each costs is that at 3,100 counties and twenty years the same choice becomes a computational one.
