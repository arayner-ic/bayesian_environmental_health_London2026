Goal of this computing lab session

The lecture made two claims that this lab puts your hands on. First, that a Laplace approximation is nothing more than a mode and a curvature. Second, that INLA works by scanning a small number of hyperparameter combinations, solving the latent field at each, and taking a weighted sum.

We will build both of those from scratch in a few lines of R, then watch R-INLA do the same thing on the Italian mortality data from the hierarchical modelling session.

What’s going to happen in this lab session?

  1. Build a Laplace approximation by hand, and see where it breaks;
  2. Build the integrated version by hand, and see what integrating buys;
  3. Refit the full pooling, no pooling and partial pooling models in INLA;
  4. Look inside the fitted object at the hyperparameter combinations INLA actually used;
  5. Vary int.strategy and strategy and watch the accuracy–speed trade-off;
  6. Inspect the precision matrix \(\boldsymbol{Q}\) and its blanks;
  7. Extend to a spatially structured bym2 model, then a spatiotemporal one;
  8. Compare against NIMBLE.

Introduction

In the hierarchical modelling session we estimated the standardised mortality ratio (SMR) for the provinces of Italy in September 2018 using three models (full pooling, no pooling and partial pooling), fitted with MCMC in NIMBLE. That workflow required initial values, burn-in, convergence checks, trace plots and \(\hat{R}\).

All three are latent Gaussian models, and they satisfy the two conditions from the lecture:

  1. the latent field (intercept, fixed effects, province effects) is Gaussian, and its links are local;
  2. there are at most one hyperparameter, the precision of the province effects.

That is why INLA can fit them deterministically.

INLA is not on CRAN. If you have not installed it yet:

install.packages(
  "INLA",
  repos = c(getOption("repos"),
            INLA = "https://inla.r-inla-download.org/R/stable"),
  dep = TRUE
)

Part 1: the two approximations, by hand

Before touching any data, we build the two approximations ourselves.

The Laplace approximation

Recall from the lecture: expand \(\log f(x)\) about its mode, where the first derivative vanishes, and keep the quadratic term. Exponentiating gives a Gaussian. The whole approximation is two numbers: the mode \(x^{*}\), and the curvature \(H = -\log f''(x^{*})\).

We will approximate a \(\text{Gamma}(5, 1)\), which is skewed but has a known answer to check against.

shape <- 5; rate <- 1

# log density, up to a constant
lf <- function(x) (shape - 1) * log(x) - rate * x

# 1. the mode
mode <- optimise(lf, c(1e-6, 50), maximum = TRUE)$maximum

# 2. the curvature there:  -f''(x) = (shape - 1) / x^2
prec <- (shape - 1) / mode^2
sdev <- 1 / sqrt(prec)

tibble(
  quantity = c("mode x*", "curvature H", "implied sd", "true mean", "true sd"),
  value    = c(mode, prec, sdev, shape / rate, sqrt(shape) / rate)
) |> kable(digits = 3)
quantity value
mode x* 4.000
curvature H 0.250
implied sd 2.000
true mean 5.000
true sd 2.236

The approximation is \(N(4, 2^2)\). Plot it against the truth:

par(mar = c(4, 4, 1, 1))
curve(dgamma(x, shape, rate), -2, 14, n = 400, lwd = 2.5, bty = "n",
      xlab = "x", ylab = "density")
curve(dnorm(x, mode, sdev), add = TRUE, n = 400, lwd = 2.5,
      lty = 2, col = "#c0392b")
abline(v = mode, lty = 3, col = "grey60")
abline(h = 0, col = "grey80")
legend("topright", bty = "n", lwd = 2.5, lty = c(1, 2),
       col = c("black", "#c0392b"),
       legend = c("Gamma(5, 1)", "Laplace approximation"))

The peak is matched exactly, which is all the method promises. But the target leans right, so its mean (5) sits above its mode (4), and a symmetric curve cannot follow. The Gaussian also has visible density below zero, where a gamma has none.

Laplace also approximates the normalising constant, which is what INLA uses to score each hyperparameter combination:

tibble(
  quantity = c("Laplace estimate", "exact (Gamma function)"),
  value    = c(exp(lf(mode)) * sqrt(2 * pi / prec), gamma(shape))
) |> kable(digits = 3)
quantity value
Laplace estimate 23.506
exact (Gamma function) 24.000

The estimate is within about 2% of the exact value.

Integrating over a hyperparameter

Laplace alone would stop at the best hyperparameter value. The integrated part of INLA is the refusal to do that.

Take a case with a known exact answer: \(x \mid \theta \sim N(0, 1/\theta)\) with \(\theta \sim \text{Gamma}(2, 2)\), so \(\theta\) is a precision, exactly as in our models. The exact marginal for \(x\) is a \(t_4\).

a <- 2; b <- 2; K <- 7

# 1. scan theta — a grid on the log scale, as INLA does
theta <- exp(seq(log(0.03), log(12), length.out = K))
w     <- dgamma(theta, a, b) * theta      # Jacobian for the log scale
w     <- w / sum(w)                       # plausibility weights

# 2. the conditional for x at each value of theta
x    <- seq(-7, 7, length.out = 400)
cond <- sapply(theta, \(t) dnorm(x, 0, 1 / sqrt(t)))

# 3. integrate: the weighted sum
marg <- as.vector(cond %*% w)

Three stages, three lines. Everything INLA does to a 168,000-element latent field has this shape.

par(mfrow = c(1, 3), mar = c(4, 4, 3, 1), cex = 0.95)

tt <- exp(seq(log(0.03), log(12), length.out = 300))
plot(tt, dgamma(tt, a, b), type = "l", log = "x", lwd = 2.5, bty = "n",
     xlab = expression(theta), ylab = "density",
     main = "1. scan the hyperparameter")
points(theta, dgamma(theta, a, b), pch = 19, col = "#c0392b",

matplot(x, cond, type = "l", lty = 1, bty = "n", lwd = 1 + 7 * w,

Middle panel is the whole idea in miniature: every blue curve is a Gaussian, none of them is the answer, and their weighted sum is a \(t\), a shape none of the ingredients had.

eval_at <- c(0, 3, 6)
tibble(
  x                = eval_at,
  truth            = dt(eval_at, 4),
  integrated       = sapply(eval_at, \(xi) sum(w * dnorm(xi, 0, 1 / sqrt(theta)))),
  `fixed theta`    = dnorm(eval_at, 0, 1 / sqrt((a - 1) / b))
) |> kable(digits = 5)
x truth integrated fixed theta
0 0.37500 0.37593 0.28209
3 0.01969 0.01974 0.02973
6 0.00119 0.00117 0.00003

Seven points recover the exact answer to three decimals. Fixing \(\theta\) at its mode gets the peak wrong and the far tail wrong by a factor of about thirty. The tail is where interval endpoints live, and this is what int.strategy = "eb" does, and precisely what it costs.

Full pooling model

Priors \[ \alpha \sim N(0, 5) \]

Likelihood \[ \begin{split} y_i &\sim \text{Pois}(\mu_i) \quad i = 1,..., N \\ \log(\mu_i) &= \log(E_i) + \alpha \end{split} \]

In INLA this is one call. Some things to notice compared to the NIMBLE version:

  • The offset goes in through E =, on the natural scale, not logged; INLA takes the log for us.
  • There is no f() term, so the hyperparameter vector \(\boldsymbol{\theta}\) is empty. There is nothing to integrate over, and Part 1’s second stage does not happen at all.
  • We match the \(N(0, 5)\) prior on \(\alpha\) via control.fixed, remember INLA parameterises Gaussians by precision, so \(\text{sd} = 5\) becomes \(\text{prec} = 1/25 = 0.04\).
t_full_inla <- system.time(
  m_pooled <- inla(
    deaths ~ 1,
    family = "poisson",
    E      = expected,
    data   = data,
    control.fixed   = list(mean.intercept = 0, prec.intercept = 0.04),
    control.compute = list(dic = TRUE, waic = TRUE, cpo = TRUE, config = TRUE)
  )
)

No pooling model

Each province gets its own fixed effect, with no borrowing of strength.

Priors \[ \alpha_j \sim N(0, 1) \quad j = 1,..., N_p \]

Likelihood \[ \begin{split} y_i &\sim \text{Pois}(\mu_i) \\ \log(\mu_i) &= \log(E_i) + \alpha_{j[i]} \end{split} \]

Province enters as a fixed effect. It still lives in the latent field, a vague Gaussian prior is still a Gaussian prior, but because there is no f() term there is still no hyperparameter.

Partial pooling model

Now the hierarchical model: a common intercept plus an IID random effect for each province, whose spread \(\sigma_p\) is estimated from the data.

Priors \[ \begin{split} \alpha &\sim N(0,5), \\ \theta_j &\sim N(0, \sigma^2_p) \quad j = 1,..., N_p \end{split} \]

Likelihood \[ \begin{split} y_i &\sim \text{Pois}(\mu_i) \quad i = 1,..., N \\ \log(\mu_i) &= \log(E_i) + \alpha + \theta_{j[i]} \end{split} \]

This is the first model with a hyperparameter, so it is the first model where Part 1’s second stage actually runs.

Instead of the half-normal prior on \(\sigma_p\) we used in NIMBLE, we use a penalised complexity (PC) prior on the precision. The parameterisation param = c(1, 0.01) reads as \(P(\sigma_p > 1) = 0.01\), we consider it unlikely that the between-province SD exceeds 1 on the log scale.

The f() term needs an integer or factor index; provincia_id is one.

pc_prec <- list(prec = list(prior = "pc.prec", param = c(1, 0.01)))

t_partial_inla <- system.time(
  m_partial <- inla(
    deaths ~ 1 + f(provincia_id, model = "iid", hyper = pc_prec),
    family = "poisson",
    E      = expected,

Part 3: the approximation choices

The lecture described two separate dials. They control different stages and are easy to confuse; the next two fits move them separately.

int.strategy: how many combinations

This governs stage 1, where the hyperparameter space gets evaluated. It is the choice you made by hand when you set K in Part 1.

fit_int <- function(strategy) {
  system.time(
    m <- inla(
      deaths ~ 1 + f(provincia_id, model = "iid", hyper = pc_prec),
      family = "poisson",
      E      = expected,
      data   = data,
      control.fixed   = list(mean.intercept = 0, prec.intercept = 0.04),
      control.compute = list(config = TRUE),
      control.inla    = list(int.strategy = strategy)
    )
  ) -> tt
  list(fit = m, time = tt[["elapsed"]])
}

r_eb   <- fit_int("eb")
r_ccd  <- fit_int("ccd")
r_grid <- fit_int("grid")
int_compare <- tibble(
  int.strategy = c("eb", "ccd", "grid"),

Prior sensitivity on the variance component

The default INLA prior on random effect precisions is loggamma(1, 5e-5). Widely used, but more informative than expected for small variances. Three priors:

  • PC prior param = c(1, 0.01): \(P(\sigma_p > 1) = 0.01\) (what we used);
  • PC prior param = c(0.1, 0.01): much tighter, allowing little between-province variation;
  • the loggamma default.

Spatial extension: BYM2

The IID model shrinks every province towards the national mean, ignoring the map. BYM2 adds spatially structured smoothing: each province is pulled towards its neighbours as well as the national mean.

\[ \begin{split} \log(\mu_i) &= \log(E_i) + \alpha + b_{j[i]} \\ \boldsymbol{b} &= \frac{1}{\sqrt{\tau_b}}\left(\sqrt{1-\phi}\,\boldsymbol{v} + \sqrt{\phi}\,\boldsymbol{u}_\star\right) \end{split} \]

where \(\boldsymbol{v}\) is IID noise, \(\boldsymbol{u}_\star\) is a scaled ICAR (neighbours-only) field, and \(\phi \in [0, 1]\) is the proportion of the variance that is spatially structured. \(\phi = 0\) recovers the IID model; \(\phi = 1\) is pure ICAR.

This is our first model with two hyperparameters, so stage 1 now scans a two-dimensional space rather than a line.

scale.model = TRUE scales the ICAR component so the precision means the same thing regardless of the graph, essential for the PC prior to be interpretable.

Closing remarks

In this lab we built both halves of INLA by hand: a Laplace approximation from a mode and a curvature, and a weighted sum over a grid of hyperparameter values. R-INLA then did the same on real data, at a scale where doing it by hand is not possible.

The two conditions from the lecture held throughout. Every model here had a Gaussian latent field with local links, and between zero and three hyperparameters. For models with many variance components, or a latent field that is not Gaussian, MCMC in NIMBLE remains the reference approach.

A common workflow is to develop and compare models in INLA, using the speed for prior sensitivity and cross-validation, then verify the final model with MCMC where the extra flexibility or exactness is needed.
